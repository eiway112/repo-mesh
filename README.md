# repo-mesh —— 跨领域治理元仓

> 一句话：**总则 = 骨架的骨架。** 技能定义骨架规范告诉你一个技能文件怎么写；本总则告诉你**一批仓怎么共存**。

**本仓是"元仓"**：它不装任何领域内容，只装「多个领域仓如何共存、如何编号、口径冲突谁裁、怎么接入、怎么发布、怎么自证」这套跨仓架构逻辑。

## 这一层管什么 / 不管什么

- **管**：跨仓的架构逻辑、编号空间、口径冲突裁决、接入登记、发布通道纪律（T1–T6，见 `总则.md`）。
- **不管**：任何领域内容。领域知识、判据、门禁全部留在各实例仓。

**分工判据**：换掉领域还成立的，写进总则；换掉领域就不成立的，留在实例仓。

## 三层架构与单向依赖

| 层 | 内容 | 依赖方向 |
| --- | --- | --- |
| 总则层（本仓） | T1–T6 治理规则、M1–M11 机检、H1–H5 人裁、MinSet/FullSet 验收分档 | — |
| 实例层（各领域仓） | 领域知识本体、各自的变更治理 | 只向上"引用/登记"，不被总则运行时依赖 |
| 运行时层 | 技能实际被加载处 | 消费实例层产物 |

**一个反直觉但正确的设计**：总则**不是运行时依赖**。接入仓不import 总则，而是靠仓根锚点声明路由回总则。这意味着总则仓即使不可达，实例仓照常跑——总则不做单点故障。这是网状（mesh）而非树状结构的由来。

## 谁需要本仓（路由）

**最终使用者不需要本仓。** 任一领域技能包自包含，获取即用——本总则不是技能的运行时依赖。

需要本仓的只有三类角色：**新建领域仓的接入者**（过 MinSet/FullSet 验收）、**跨仓口径冲突的裁决方**、**治理门禁的执行者**。

路由入口：每个接入仓在仓根锚点声明（判据 A1）中登记"总则采用版本"，该声明随技能仓自身分发。

## 目录结构

```
repo-mesh/
├── README.md ← 本文件
├── LICENSE          ← MIT
├── 总则.md                     ← T1–T6 治理条文（机检 M1–M11 的对象）
├── 接入登记册.md                ← 一行一仓，唯一台账（领域名的唯一合法栖身处）
├── validate_governance.py      ← 门禁脚本（退出码 0=干净 / 2=有发现 / 1=未能执行）
├── 冻结基准.md                  ← 版本冻结记录（git blob id 为主判据）
├── 行业专家_跨领域治理总则_策划方案.md ← 演进史：总则怎么来的 + K1–K6 思想底座的唯一落盘载体（非模板）
└── reports/                    ← 试套报告、门禁自证记录
```

## 接入方式

新领域仓按两档接入（判据详见 `总则.md` 第四章）：

- **MinSet（最小接入集）**：零脚本可达——仓根锚点声明、前缀登记、红线 ≥1 条（编号+触发条件+违反后果）、SKILL.md `version` 字段、动作段、共用声明。
- **FullSet（完整接入集）**：MinSet + 八块骨架、变更定级、接口契约、同步器、门禁脚本、冻结基准、判据三件套。

流程：建仓 → 领域前缀登记 → 填登记行 → 过对应档位验收表。

## 机检与人裁分账

- **机检 M1–M11**：能机器判的进 M。退出码三值，**"没跑成"绝不静默当"通过"**（检查对象为 0 时退出码 1）。
- **人裁 H1–H5**：只能人判的进 H。两本账不混，**机检全过 ≠ 合格**。

跑法：

```bash
python validate_governance.py         # 退出码 0/2/1
```

### 配置黑名单（重要）

黑名单**不写死在脚本里**——否则本脚本一旦分发，等于把维护者身份与业务领域一并公开。

- 脚本内置**示例值**（占位性质的示例词，非真实内容），保证开箱可跑。
- 使用者按自己情况建 `names.local.json`（已 `.gitignore`）覆盖。**仓内 `names.local.json.example` 是可直接复制的模板**，本README 不重复内嵌其内容——理由见下方警告。

> ⚠️ **为什么这里不贴一段 JSON 样例**：本仓 M11 扫一切文本文件（含本文），而贴出来的样例词会被使用者
> 原样抄进 `names.local.json` 当黑名单——于是门禁对着 README 里那段样例自己报 FAIL。
> 换任何示例词都躲不开：**在文档里展示配置样例，与"文档也在扫描面内"这两件事不可兼得。**
> 同理，README 里连"示例词长什么样"都不写——**解释这件事本身就会把词写进扫描面。**
> 故样例只放在 `names.local.json.example` 一个文件里，本README 只给指针。

- 删掉该文件会回落到内置示例值；**不会**变成空名单导致 M8/M9 因"无对象"而 FAIL。
- **但要知道自己此刻在哪个态**：脚本**不会**告诉你当前用的是示例值还是你的真实配置——两种态都输出 PASS。
  判别方法：`names.local.json` 不存在 ⇒ 用的是示例值 ⇒ 你的真实姓名/领域名即使写进仓内也**不会被抓出来**。
  这不是脚本缺陷（它无法自证黑名单是哪一份，见 §4.6 冻结说明），是**流程要求**：发布前先确认该文件在。
  示例文件见仓内 `names.local.json.example`（若存在）。

## 本仓纪律

1. 依赖单向向下：严禁实例仓反向定义总则规则；严禁总则持有领域内容（正文零领域名，机检 M8）。
2. 引用不复制：沿用外部机制一律走路径引用（台账见 `总则.md` §2.5），禁止复制实例仓治理文件正文。
3. 发布通道唯一；公开仓推送前必须先声明推到哪、谁能看见；推送与否以远端回读为准。
   - **自动化推送的边界（2026-10-08 维护者裁定，修订 T5 第 2 条）**：
     - **仍禁止**：公开仓的**首次创建**、**重大版本发布**、**内容变更的定性**——这些属对外承诺，须人工审定后推送。
     - **允许**：内容经审定入库后，向**已审定镜像目标**的**单向机械镜像**（显式列出要同步的 ref，不含任何内容决策）。**不用 `git push --mirror`**：实测 Gitee 拒绝该命令（`deny updating a hidden ref`）且是部分成功——main 推了、tags 全丢、退出码非0，而同一命令在 GitHub 侧自测会过。
     - **为什么开这个口子**：纪律要防的是"未经人看一眼就发出去"，不是防"已审定内容的多平台分发"。不分发反而会诱发手工拷贝，直接违反本条第 3 点前半句"发布通道唯一"。
     - **镜像必须单向**：源 → 镜像，镜像侧不得反向写入。方向唯一是"结构上不可能分叉"的唯一保证；双向同步必然产生冲突与漂移。
     - **镜像的代价（须知情）**：镜像侧任何手工提交会被下一次推送覆盖。这是设计意图，不是缺陷。
4. 每次修订后实跑 `validate_governance.py`；新增门禁须做缺陷注入自证；机检与人裁分账，不许互相抵账。
5. **借鉴不产生追平上游的义务**：借鉴外部架构只按需融入逻辑。三问判据——① 本仓是否真的**消费**它（代码依赖/常量引用），还是只借鉴思路？② 本仓该机制的需求是否**内生**？③ 若上游把它删了，本仓会不会**照跑**？三问皆负则不开批。

## 开源口径

- MIT，版权方见 `LICENSE`。
- **零本机路径、零真名、零项目名、零客户名**。这条由 M11 常态机检保障，扫描面＝**仓内一切文本文件**（按内容判定，不依赖扩展名白名单；v0.8.0 起。v0.7.0 曾把扫描面从显式文件名单改为全仓，但仍用 `.md/.py/.json` 后缀白名单，实测漏掉 `.github/workflows/*.yml`，见脚本注释中的两轮治本说明）。
- **⚠️ 使用前必读：`names.local.json` 必须存在**。M8/M9/M11 的禁现能力全部来自它。该文件已 `.gitignore`（它就是维护者身份本身，不该进版本库），**克隆后不会自动出现**；缺失时脚本回落到内置示例值并**照常 PASS**——此时判据形同虚设而门禁显示全绿。按总则 §4.5「未标注的降级 = 未降级」，该状态应读作**未达标**。示例见下方"配置黑名单"。
- **git 历史不在 M11 扫描面内**：M11 扫的是工作树。私有仓转公开时，历史会随分支一并公开，须单独逐提交扫描（`git rev-list main`逐枚 `git grep`），不能只看 tip。本仓该问题曾以 D8 登记，**已于 v1.8 处置：公开仓历史重建为单一提交，重建前逐提交复扫确认零敏感项**。
- 文档中的领域名与远端一律用占位符（`{实例仓A}` / `{本仓远端}` 等）。**这是刻意的**：一个跨领域标准若带着某个具体行业的素材，就不是标准，而是某个项目的附件。
- 冻结基准主判据＝ git blob 对象 id（内容寻址，与平台/行尾/文件系统无关），辅助＝字节数 + sha256。

## 这个仓想解决什么

多数治理仓只有"规则"，没有"规则会咬人"的证据。本仓把自证过程也留痕——门禁抓到作者自己身上的失实、注入缺陷时被绕过、五次同族过程错误，全部逐条登记在 `reports/`。**可失败的诚实，是治理机制真正生效的唯一可信标志。**
